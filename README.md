# PasskeySecurity 公開用候補（未公開・新規導入専用）

EC-CUBE 4.3.1-p1 / PHP 8.3 / Symfony 6.4を対象にした開発候補です。
店舗向けにカスタマイズされた旧版からそのまま更新する用途ではありません。旧epochだけを持つ環境への変換は拒否します。

## 初期動作

- 会員のパスキーは任意です。マイページに設定リンクを追加します。
- 従来のパスワードログイン・EC-CUBE標準の設定を維持します。
- スタッフの追加認証も初期状態は任意です。ただし、本人が登録を完了したアカウントには以後その認証を要求します。
- スタッフはパスキー、またはパスワード＋TOTPを選べます。両方を毎回要求しません。
- EC-CUBE標準2FAを併用する場合は、標準2FAの初回登録・認証を済ませてから、プラグインのスタッフ追加認証を行います。管理画面の利用には両方の条件を満たす必要があります。
- 会員やスタッフのパスワード、既存認証器、会員データを導入時に変更しません。
- 自動でメール送信、SMTP切替、worker起動、DNS・Webサーバー変更をしません。

## 導入時の準備

HTTPSと、32文字以上の強いECCUBE_AUTH_MAGICが必要です。HTTPS・証明書・proxyの構築はプラグインでは行いません。
有効化後、認証済みシステム管理者がプラグインの設定画面で店舗URLを確認して保存します。有効化時にOriginを自動登録しません。
未準備でも店舗全体や従来のログインを停止しません。匿名の初回訪問からHostを自動採用することはありません。

店舗のOrigin/RP IDは初期登録後に変更しません。ドメイン変更時はパスキー移行の設計が必要です。
全スタッフの必須化は、システム管理者本人が追加認証を登録・確認してから設定画面で選べます。
会員の一斉パスワード変更の管理UIは、この候補ではまだ提供していません。導入だけでフラグを立てません。

## 秘密設定とバックアップ

TOTP等の暗号鍵は、既存のECCUBE_AUTH_MAGICとプラグインDB内のランダムsaltから、専用のHKDF用途名で導出します。
追加の平文鍵ファイルを公開領域へ作成しません。DBにTOTPの平文を保存しません。
バックアップにはDB全体とECCUBE_AUTH_MAGICが必要です。AUTH_MAGICやsaltを単独で変更・再生成しないでください。
秘密値をGit・チャット・公開バックアップに保存しないでください。

## 無効化・アンインストールと再導入

- 無効化中やアンインストール中は、このプラグインによるパスキー認証・スタッフ追加認証は動作しません。EC-CUBE標準の認証設定も含めて、事前に代替手段と影響を確認してください。
- この候補はアンインストール時に専用DBテーブルを削除しません。Origin、スタッフ必須設定、パスキー情報、暗号化されたTOTP秘密値、復旧・監査・試行制限情報などは残ります。EC-CUBE自体のプラグイン登録とファイルの扱いは導入方法に依存するため確認してください。
- 残存データを保持して再導入・有効化すると、初期状態に戻すのではなく、保存済みのOriginと認証設定を引き続き使用します。既存の必須化設定も維持されます。同じDBとECCUBE_AUTH_MAGICを維持してください。
- 認証データの完全削除は自動実行しません。削除はパスキーや復旧・監査情報を失うため、本人確認、代替認証、保存期間とバックアップを確認し、別途手順を定めてください。アンインストールだけでデータが消去されたと扱わないでください。

## 紛失時の復旧

スタッフの最後のパスキーは本人画面から削除できません。
すべての認証器を紛失した場合は、管理担当者の独立した本人確認が必要です。
既存のrecover-staffコマンドは、プロジェクト外の私有証跡と私有出力ファイルを使います。
復旧コードを確認し、新しいパスワードと認証器を登録します。単なるパスワード入力で既存MFAを解除しません。
この復旧経路の公開版ブラウザ一巡試験は未完了です。

## 時計逆行時のログと再試行

時計逆行の検出時は認証を503で停止し、Retry-After: 2とno-storeを返します。画面の照会番号（X-PasskeySecurity-Incident）を管理担当者へ伝えてください。パスワード・認証コード・復旧コードは伝えないでください。

- 自動再送は行いません。同じCookieを保持し、2秒以上待って画面をGETで開き直し、現在の状態を確認します。フォームのPOSTをブラウザで再読込みしないでください。
- 管理画面へ入れる場合は、認証コードを再送しません。追加認証が必要なら通常の本人確認を行い、使用済みTOTPを再送しません。403・期限切れ・再度の503を繰り返して回避しないでください。
- 復旧コードが使用済みなら再使用せず、同じセッションから残りの手順を続けます。パスワード変更後なら再変更せず、現在のパスワードで認証器登録を続けます。状態が判別できない場合は操作を止め、管理担当者が復旧状態を確認します。
- パスキーでは古いチャレンジや署名を再送しません。登録一覧を確認し、必要な場合だけ新しいチャレンジから開始します。失効・設定変更も現在の一覧・設定を確認してから操作します。
- 通信切断・タイムアウト・500も結果不明として扱います。照会番号の有無だけで未処理・成功を判断しません。確認後の手動操作は1回までとし、再度失敗したら管理担当者へ連絡します。

プラグイン専用のJSONログは、kernel.logs_dir配下の環境名/passkey_security_clock.jsonlへ0600で出力します。warningのclock_rollbackイベントに、照会番号・処理箇所・判定時刻の前後値・単調時計・PIDを記録します。ユーザー、IP、URL、セッション、認証証明、パスワード、TOTP秘密、チケット、例外オブジェクトは記録しません。ログ書込み失敗時も503を維持し、PHPエラーログに秘密を含まないclock_event_log_failedを出力します。記録の永続化は保証しないため、ログ不達も監視してください。

時刻同期、全ノードの監視、ログの権限・容量・ローテーション・保存期間・バックアップ復元後の旧ログとの分離は運用管理者の担当です。プラグインはログ削除、時刻補正、認証データの初期化を行いません。保存期間は通常30日を運用案とし、正式な保管規程に合わせて決定してください。

## 対応範囲

現時点では未公開の候補です。店舗復旧専用のTurnstileゲート、スタッフメール登録/通知、
旧形式メールアドレス救済、店舗の再開用一斉変更機能は配布対象から除いています。
標準ログインのCSRF・アクセス権限・ネイティブ認証を使用し、WebAuthnは厳密なHTTPS Originと署名を検証します。
合成環境のCLIで導入・更新・無効化・再有効化・アンインストール・再導入を確認したDBは、PostgreSQL 16、MySQL 8.4、MariaDB 11.4です。TOTPとスタッフの復旧はHTTPS上で確認しています。管理画面からのZIP導入と実機のパスキー認証器は未検証です。

## 配布と開発支援

PasskeySecurityはGitHub Releasesで無料配布する方針です。開発・保守への支援は任意で、支援の有無にかかわらず同じ配布物を利用できます。

PasskeySecurity本体は[MITライセンス](LICENSE)で提供します。同梱ライブラリの著作権表示とライセンスは `Resource/dependencies/` に収録しています。
